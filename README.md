# Manuel Paez — academic website

Static HTML hosted on GitHub Pages. Navigation and page content require no client-side JavaScript; ML articles optionally enhance math and code with JavaScript.

## Editing and building

Edit `scripts/build_site.py` for biographies, publication records, project records,
code descriptions, and shared headers. It is the shared generator for the HTML
pages; ML notebook content and article generation live in `scripts/ml_notes.py`.
Do not edit generated HTML directly. Edit `src/styles.css` for styling.

Run `npm ci` when dependencies are absent, then `npm run build` and `npm run check`.
Commit generated HTML and `styles.css` along with their sources. `node_modules/`
is local-only; `package-lock.json` remains tracked. The original CSS-only command,
`npm run build-css`, is also available.

## ML Research Notes

`ml-notes.html` is generated by `scripts/ml_notes.py` through the existing build.
The shared header includes ML Research Notes between Projects and Code on every
page. Notebook styling lives in `src/styles.css`; generated `styles.css` is committed.
The landing page needs no JavaScript. Articles load pinned MathJax 3.2.2 and
Prism 1.29.0 from jsDelivr for equations and Python/PyTorch syntax highlighting.
Without these scripts, prose and code remain readable and math remains LaTeX.

### Add a training report or mathematical note

1. Choose a stable lowercase hyphenated slug and category. Reports use
   `training-reports`; notes use `pretraining`, `optimization`, `architectures`,
   `generalization`, `inference-and-sampling`, or `reinforcement-learning`.
   Independent investigations use `research`.
2. Copy `ml-notes/_templates/article.html` to
   `ml-notes/_articles/<category>/<slug>.html` (create the category directory).
   This file is an HTML **body fragment**, not a full page. Replace the formatting
   examples with your article and remove unused sections. The shared page wrapper,
   navigation, metadata, scripts, and dates are generated automatically.
3. Copy the object in `ml-notes/_templates/entry.json` into the array in
   `ml-notes/entries.json` only when the article is ready to publish. Set its
   `category`, `slug`, `title`, `description`, ISO `published`/`updated` dates,
   and `topics`. Reports require a unique `report_id` such as `TR-001`;
   omit that field for mathematical notes. The registry starts empty deliberately.
4. Add available supporting links to `links` as `[label, URL]` pairs, for example
   labels `PDF`, `Code`, or `Experiment logs`. Use actual verified URLs only.
   Local link URLs in this registry are relative to the repository root.
   The generated article itself is linked automatically from the landing page;
   entries are sorted newest publication first within each category.
5. Store figures in `ml-notes/figures/` and supporting PDFs, data, or logs in
   `ml-notes/materials/`, preferably in per-article subdirectories. In the article
   body, paths are relative to the generated page: `../figures/<filename>` or
   `../materials/<filename>`. Include meaningful alt text, captions, table headers,
   and references. Use `\(...\)` for inline LaTeX and `\[...\]` for unnumbered
   displays; `equation`/`align` environments receive automatic equation numbers.
   Use `\label{eq:name}` and `\eqref{eq:name}` for equation cross-references.
   Theorem, lemma, proposition, and definition blocks use `class="statement"`;
   their names and numbers are explicit editorial text, as shown in the template.
   Both Python and PyTorch use `<pre><code class="language-python">`.
   Escape `&` and `<` in code as `&amp;` and `&lt;`.
6. Run `npm run build` and `npm run check`. Review the generated
   `ml-notes/<category>/<slug>.html` and landing-page entry, then commit the source,
   registry, assets, generated HTML, and CSS together when ready. Nothing in the
   build pushes or deploys the site.

Unregistered article bodies and templates are under underscore-prefixed directories,
which the existing default GitHub Pages/Jekyll processing excludes. Do not add
`.nojekyll` or explicitly include these directories without revisiting this exclusion.
Only register finished articles; source templates must never be landing-page entries.
Removing an entry from the registry does not delete its generated HTML: remove that
specific generated file as well if withdrawing an article.

### Preview and verify the template

```sh
npm run build
python3 scripts/build_site.py --preview-template
npm run check
python3 -m http.server 8000 --bind 127.0.0.1
```

Open `http://127.0.0.1:8000/ml-notes.html` and
`http://127.0.0.1:8000/ml-notes/_preview/article.html`. The latter is an explicitly
unpublished formatting fixture, ignored by Git and excluded by GitHub Pages. Check
inline/display math, equation (1) and its reference, code colors/indentation,
figure/caption, and table. Check desktop and 320–375px mobile widths; wide code,
math, and tables should scroll inside their containers, not widen the page.
`npm run check` verifies shared navigation order, local assets/links, HTML structure,
metadata, categories, resource inclusion, and registered article outputs.
